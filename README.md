# Salesforce → Process Intelligence → Value Case

Takes lead-to-close data out of Salesforce, turns it into a process-mining event log
(CSV and XES, ready for process mining tools), mines it for bottlenecks and deviations, and sizes the
dollar value of fixing them in an interactive dashboard.

**Live site: https://salesforce-process-intelligence.vercel.app** (an [overview](https://salesforce-process-intelligence.vercel.app) with the value items, business case and live Salesforce run, plus the interactive [process analysis](https://salesforce-process-intelligence.vercel.app/dashboard.html))

![Landing page](docs/img/landing.png)

Pure Python standard library: no `pip install` needed.

**What's here**

| | |
|---|---|
| Overview | `site/index.html`: headline value, the three value items, the re-quote business case, approach, live Salesforce run and downloads |
| Process analysis | `site/dashboard.html`: process map, paths, bottlenecks, interactive value model (10-month dataset) |
| Live extract | `data/live/event_log.csv` / `.xes`: pulled from a real Salesforce trial org (shown on the overview) |
| Event logs | `data/event_log.csv` / `.xes` (10-month dataset), `data/live/event_log.csv` / `.xes` (live org) |
| Decks | `deck/salesforce-process-intelligence.pptx` (story) and `deck/salesforce-process-intelligence-tech-setup.pptx` (tech setup), with PDFs; both generated by `deck/build_deck.js` (`DECK_KIND=tech` for the second) |
| Talk track | `docs/talk-track.md` |

```
pipeline/
  sf_client.py        REST client; requests are signed by the Salesforce CLI session
  extract.py          SOQL: Lead, Opportunity, OpportunityHistory, Task -> raw.json
  seed.py             Loads [Demo] deals into an org and walks them through stages
  synthesize.py       Same schema, 10 months of simulated history with planted issues
  transform.py        raw.json -> event_log.csv + event_log.xes
  mine.py             process map, variants, cohorts, value model -> insights.json
  build_dashboard.py  insights.json -> dashboard/index.html (single page)
  build_site.py       all pages + downloadable logs -> site/
dashboard/            page templates
deck/                 deck generator (pptxgenjs): story deck and tech setup deck
site/                 static build, deployable as-is
```

Set `PI_DATA=data/live` to run `transform.py` / `mine.py` against the live extract.

## Run it

Demo data (works offline):

```bash
python3 pipeline/synthesize.py && python3 pipeline/transform.py && python3 pipeline/mine.py && python3 pipeline/build_dashboard.py
```

Live Salesforce trial org:

```bash
sf org login web --alias trial --instance-url https://<your-domain>.my.salesforce.com
```

```bash
python3 pipeline/seed.py --target-org trial --deals 40
```

```bash
python3 pipeline/extract.py --target-org trial --out data/live/raw.json && PI_DATA=data/live python3 pipeline/transform.py && PI_DATA=data/live python3 pipeline/mine.py
```

Build the site:

```bash
python3 pipeline/build_site.py
```

`seed.py --cleanup` removes everything it created (all seeded records are prefixed `[Demo]`).

Notes from setting up a new trial org:
- New orgs block uninstalled connected apps. Allow the CLI under Setup → Connected Apps OAuth Usage → Salesforce CLI → Install.
- Newer Starter orgs use a shorter sales process (Qualify → Meet & Present → Propose → Negotiate). `seed.py` and `mine.py` detect it and map stages.
- The CLI redacts access tokens in its output, so `sf_client.py` sends requests through `sf api request rest` and never handles the token.

## Load into a process mining tool

Upload `data/event_log.csv` (or the `.xes`) to a process mining tool such as Apromore. Map the columns:

| Column | Role |
|---|---|
| `case_id` | Case ID |
| `activity` | Activity |
| `start_time` / `end_time` | Start / End timestamp (`yyyy-MM-dd HH:mm:ss`) |
| `resource` | Resource |
| `region`, `industry`, `lead_source`, `amount`, `discount_pct`, `outcome`, `owner` | Case attributes |
| `source_object` | Event attribute |

## Data model

| Event log field | Salesforce source |
|---|---|
| Case ID | `Opportunity.Id` |
| `Lead Created` | `Lead.CreatedDate`, joined by `Lead.ConvertedOpportunityId` |
| Stage activities | `OpportunityHistory.StageName` / `CreatedDate` (repeated rows collapsed to real stage changes) |
| Task activities | `Task.Subject`, `CreatedDate` → `CompletedDateTime`, joined by `Task.WhatId` |
| Case attributes | `Opportunity.Amount`, `LeadSource`, `IsWon`, `Owner.Name`, `Account.Industry`, `Account.BillingCountry` |

## Why the demo data is simulated

`OpportunityHistory.CreatedDate` is system-set and can't be backdated, so a
trial org only holds minutes of history. `synthesize.py` writes the exact shape
`extract.py` produces, so every downstream step is identical; only the source changes.
The planted issues (EMEA approval delays, re-quote loops, skipped Qualification) are
listed at the top of that file, and the dashboard is labelled as demo data.

## Value model

`value = deals in scope per year × win-rate gap (problem cohort vs clean cohort) × average won deal × share of gap closed`

Cohorts compare like with like (re-quotes are measured only among deals that reached
Negotiation). Cycle-time gains are reported but not counted in the total. Drivers can
overlap on the same deal, so the sum is an upper bound until validated deal by deal.
